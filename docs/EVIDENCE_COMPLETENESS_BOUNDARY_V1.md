# Evidence Completeness Boundary v1

## Core rule
The existence of one supporting Evidence item does not by itself mean the available evidence set is complete.

## Product meaning
- `SUPPORTED` means the Fact has valid supporting Evidence under its contract;
- it does not mean every relevant official source, filing, period, or contrary observation has been collected;
- Assessment/Inspect must not translate `has Evidence` into `all evidence reviewed` unless an explicit completeness contract proves that scope.

## Required restraint
- missing expected source coverage must remain distinguishable from provider-confirmed absence;
- conflicting Evidence must remain visible rather than being omitted to create a clean narrative;
- incomplete historical coverage must not be presented as a complete trend;
- collection success for one provider does not imply coverage success for another provider.

## Future completeness claims
Any future label such as `complete`, `all filings checked`, or `full market coverage` requires an explicit bounded scope and a reproducible coverage check.

## Implementation boundary
Coverage ledgers, completeness calculators, collection monitoring, UI badges, and tests are CODEX-FIRST/later work.
