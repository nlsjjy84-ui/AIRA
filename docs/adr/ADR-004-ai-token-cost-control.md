# ADR-004: AI 토큰 및 비용 통제

- 상태: Accepted
- 기준일: 2026-08-14

## Context

동일 정보에 대한 반복 AI 호출은 비용과 지연을 증가시키고 결과 일관성을 낮춘다. 사용자별로 공통 분석을 반복하면 사용자 증가가 AI 비용 증가로 직접 연결된다. AI 공급자 장애나 가격 변화에 핵심 서비스가 과도하게 종속될 위험도 있다.

## Decision

AI 호출 전에 정규화, 중복 제거, 규칙 기반 처리, 기존 결과와 캐시 확인 및 중요도 판단을 우선한다.

- AI는 필요한 작업에만 호출한다.
- 동일 Event와 Assessment의 공통 분석을 저장하고 재사용한다.
- 사용자 수만큼 동일한 분석을 반복하지 않고 전달 단계만 필요한 수준에서 개인화한다.
- AIExecution으로 provider, model, task type, prompt/version, 입력·출력 토큰, 비용, 지연, 성공·실패와 cache hit 여부를 추적할 수 있게 한다.
- 민감정보, API Key와 인증 토큰을 AI 입력·로그에 저장하지 않는다.
- 특정 모델과 공급자를 교체할 수 있는 경계를 유지한다.

## Alternatives Considered

1. **모든 수집 문서를 즉시 AI 분석**: 구현은 직관적이나 중복·저가치 호출과 비용 증가가 크다.
2. **사용자별 맞춤 분석 생성**: 개인화는 쉽지만 공통 지식이 사용자 수만큼 반복된다.
3. **토큰 총량만 집계**: 단순하지만 어떤 기능과 모델이 비용을 만드는지 개선하기 어렵다.
4. **단일 AI 공급자에 직접 결합**: 초기 개발은 빠르지만 장애, 가격 및 모델 변경에 취약하다.

## Consequences

- AI 호출 이전의 데이터 품질, 중복 제거와 캐시 정책이 중요해진다.
- 공통 분석과 사용자 전달의 책임을 분리해야 한다.
- 기능·모델·기간별 비용과 품질을 비교할 수 있다.
- 캐시 무효화, prompt/version 관리와 재분석 기준을 운영 정책으로 정의해야 한다.
