# ADR-003: 개인정보 최소수집과 비수집 정책

- 상태: Accepted
- 기준일: 2026-08-14

## Context

미래에 사용할 가능성이나 보안·모니터링 편의를 이유로 개인정보를 축적하면 침해 영향, 규제 부담과 운영 복잡성이 증가한다. 현재 AIRA의 핵심 정보 기능에는 광범위한 신원·위치·기기 추적 정보가 필요하지 않다.

## Decision

계정 운영과 명시된 기능에 필요한 최소한의 사용자 데이터만 수집한다.

- 신규 수집 전 목적, 최소 대안, 저장 위치, 접근자, 보존 기간과 삭제 시점을 검토한다.
- 필요성이 없다면 실명, 성별, 생년월일, 주소, 직업과 전화번호를 수집하지 않는다.
- Wi-Fi SSID·BSSID·MAC, Bluetooth MAC·주변 기기 목록, Wi-Fi 접속 이력, 이동 경로와 과거 접속 장소를 기본적으로 수집·저장하지 않는다.
- 보안 기능이나 모니터링을 이유로 영구적인 사용자 추적 데이터를 만들지 않는다.
- 수집 항목과 함께 명시적인 비수집 항목도 정책으로 관리한다.

## Alternatives Considered

1. **향후 활용을 위한 선제 수집**: 미래 기능 개발은 쉬울 수 있으나 현재 목적 없는 보유 위험이 크다.
2. **기기 물리 식별자 기반 이상 탐지**: 일부 탐지에 유용하지만 지속적인 사용자 추적과 오탐·프라이버시 위험이 있다.
3. **모든 로그 장기 보존**: 사후 분석에는 유리하지만 민감정보 노출 범위와 비용을 증가시킨다.

## Consequences

- 개인정보 침해 시 영향과 규제·운영 부담을 줄인다.
- 일부 개인화 및 이상 탐지는 필요한 시점에 별도 검토가 필요하다.
- 신규 데이터 수집은 기능 요구만으로 자동 승인되지 않으며 목적과 수명주기를 문서화해야 한다.
- 비수집 정책을 변경하려면 Architecture 검토와 ADR이 필요하다.
