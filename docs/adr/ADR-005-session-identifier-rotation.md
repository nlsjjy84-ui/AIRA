# ADR-005: 내부 사용자 ID와 세션 식별자 분리 및 회전

- 상태: Accepted
- 기준일: 2026-08-14

## Context

안정적인 내부 사용자 ID를 외부 세션 식별자로 재사용하면 계정 추적, 식별자 추측과 세션 고정 위험이 증가한다. 순차번호나 규칙 기반 식별자는 예측 가능하며, 영구적인 기기 물리 식별자는 사용자를 장기간 추적하는 수단이 될 수 있다.

## Decision

내부 계정 식별자와 외부 인증·세션 식별자를 분리한다.

- 내부 `user_id`는 내부 관계의 안정성을 위해 유지하되 외부에 불필요하게 노출하지 않는다.
- 외부 세션 식별자는 암호학적으로 안전한 난수 기반 opaque identifier를 사용한다.
- 순차번호 또는 예측 가능한 ASCII 규칙 기반 식별자를 사용하지 않는다.
- 로그인, 재인증, 권한 변경과 토큰 갱신 등 적절한 보안 경계에서 세션 식별자를 회전한다.
- 만료와 로그아웃 시 세션을 폐기한다.
- 인증·세션 토큰 원문을 로그에 기록하지 않는다.
- Wi-Fi/Bluetooth MAC 등 영구적인 기기 물리 식별자를 사용자 추적 수단으로 사용하지 않는다.

## Alternatives Considered

1. **내부 user_id를 세션 ID로 사용**: 단순하지만 예측과 장기 상관관계 분석이 가능하다.
2. **로그인 후 고정 세션 ID 유지**: 구현은 간단하지만 세션 고정과 탈취 영향이 커진다.
3. **기기 MAC 기반 식별**: 지속성은 높지만 프라이버시 침해, 위·변조 및 플랫폼 제약 문제가 있다.
4. **규칙 기반 사용자 친화 식별자**: 디버깅은 쉽지만 엔트로피가 부족하고 정보가 노출될 수 있다.

## Consequences

- 세션 저장소는 회전, 만료, 폐기와 동시 세션 정책을 지원해야 한다.
- 로그와 추적 시스템은 토큰 원문 없이 요청을 진단할 수 있는 안전한 상관관계 수단이 필요하다.
- 내부 사용자 관계는 안정적으로 유지하면서 외부 세션 간 연결 가능성을 줄인다.
- 인증 구현 시 안전한 난수 생성기, 만료 정책과 회전 테스트가 필수다.
